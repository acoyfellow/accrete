Freeze the work once. Fork it for every job.

A model writes a plan. The plan does slow setup, then waits for a diff. Amber can freeze the plan at that point. Accrete keeps the frozen copy. Every new diff starts from the frozen copy, not from the top.

    What we found

    Four evals, all with receipts in amber-accrete/bench. The question: when a model writes the plan, does a frozen copy beat a plain cache?

    evalplansfrozencache or replay
    prompt asks for a run id in setup12,264 tokens · 10/1022,681 tokens · 0 cache hits
    neutral prompt, review diffs10≈2,270 tokens · 10/10≈2,270 tokens · 10/10
    ask a person about 5 issues105 questions · right issuessame, 0 of 10 broke
    planted Math.random plan15 questions40 questions · wrong issues
    a new issue opens mid-run10keeps the first viewcached: same · fresh read: a 6th question

    So

    Freezing wins when a plan is not repeatable: randomness, the clock, or data that changes. In 30 plans the model wrote without a hint, it wrote none of those. A cache was enough.

    freeze   = keep the exact moment, resume it anywhere
cache    = run again, answer setup from memory
use both = freeze when the plan is not repeatable,
           cache when it is
